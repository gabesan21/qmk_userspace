# Plan — [[1.2.2-phase-verification]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** reparar os 3 defeitos confirmados pelo dono na 1ª execução do `scripts/build_flash.sh`: (1) retrabalho visual real do CLI (hierarquia, seções, saída polida); (2) preflight passa a **executar** as correções (`git submodule update --init modules/bastardkb`, `qmk setup -b main bastardkb/bastardkb-qmk`) em vez de só instruir; (3) o corretivo do `user.qmk_home` inclui `-b main`. Sincronizar a spec `pop/specs/build-flash-script.md` com o novo contrato.
- **Observable result:** o dono roda o script e vê um CLI com hierarquia clara; num ambiente quebrado o preflight corrige sozinho e segue; o comando documentado do `qmk setup` funciona (`main`, não `master`).

## Strategy

Uma frente coesa: reescrever as seções de saída/preflight do script (mantendo argumentos, códigos de saída, fluxo compile→flash e fail-fast) e sincronizar a spec na mesma entrega — são o mesmo contrato mudando de "detecta e instrui" para "detecta e executa".

Decisões que vinculam a execução:

- **Auto-fix sem prompt de confirmação.** Comando explícito do dono ("o script deveria simplesmente executá-los") cobre as duas correções; o `qmk setup` é o caminho documentado do próprio QMK e aponta para o fork declarado do projeto — não é destrutivo no sentido de sobrescrever trabalho do dono. Um prompt adicionaria fricção exatamente no cenário (ambiente novo) que a mudança quer zerar.
- **Guarda pós-fix:** após executar cada correção, o script revalida a condição; se ainda falhar, erro + saída `1` (fail-fast preservado). Em ambiente sadio (máquina do dono, confirmado pelo `qmk doctor`) os fixes são no-op.
- **Limite do auto-fix:** somente as duas correções nomeadas pelo dono. `qmk` CLI ausente segue detecta-e-instrui (instalar programas é decisão do dono e estava fora do escopo já aprovado).
- **Visual:** hierarquia de seções, cabeçalho/sumário e saída polida — mais do que cores pontuais; mantém pt-BR, `NO_COLOR` e detecção de TTY.
- Execução do script (build/flash real) continua reservada ao dono.

## Risks and abort conditions

- **Risk:** auto-fix mascarar falha real (fix roda, ambiente continua quebrado) — mitigação: revalidação pós-fix com fail-fast (saída `1`).
- **Risk:** `qmk setup` interativo travar o script — mitigação: execução direta conforme comando do dono; se na prática travar, o dono reporta na verificação humana.
- **Risk:** retrabalho visual virar enfeite sem hierarquia — mitigação: critério C1 exige hierarquia/seções/sumário observáveis no `--help` e na leitura.
- **Abort if:** o ambiente do executor não permitir sequer `bash -n`/leitura do script, ou a spec estiver divergente do card além do delta previsto — `blocked: true` com evidência.
